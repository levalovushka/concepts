# Пайплайн v5: от фразы к приложению уровня Revolut

Статус: **принятая спека**. Заменяет v4. Старый `native/` снесён, HTML-контур закрывается.
Предыстория провала v4 — [WHY-REWORK.md](WHY-REWORK.md).

---

## 1. Почему v4 провалился

Не потому, что мало layout'ов. Три системные ошибки:

1. **Фиксированная библиотека layout'ов.** 12 шаблонов, в которые заталкиваются данные. Настоящие
   приложения так не устроены — на выходе неизбежно «шаблон с подписями».
2. **Не было эталона.** Планка «хорошо» придумывалась из головы, поэтому каждый круг правок бил
   мимо.
3. **Экран рождался из категории, а не из идеи продукта.** «Соцсеть» → generic-лента ВК, хотя
   «Образы» про образ из гардероба с отметками вещей.

## 2. Планка

**Эталон — топовые продуктовые приложения: Revolut, Wise и подобные с Mobbin.** Не «прилично для
концепта», а уровень, на который смотрят как на референс.

Приоритет при конфликте: **визуальное качество и UX выше достоверности доступов.** Доступы —
второй приоритет (раньше было наоборот, это и держало планку внизу).

Результат смотрит ревьюер **по скриншотам**, поэтому каждый экран обязан держать удар статикой.

## 3. Жёсткие правила

- **Изображений нет. Только SF Symbols.** Генерация картинок — не сейчас. Значит эстетика строится
  на типографике, карточках, градиентах, цвете и иконографии — ровно то, на чём построены
  Revolut и Wise.
- **Ноль визуальных багов.** Перекрытия, обрезания, кривые отступы, слабый контраст, рассогласованные
  иконки, отсутствующие состояния нажатия — блокеры.
- **Всё работает.** Анимации переходов, состояния нажатия, жесты, загрузка/пусто/ошибка, реальный
  ввод. Мёртвая статика — дефект.
- **Экран выводится из идеи продукта**, а не из шаблона категории. Перед экраном отвечаем: какую
  задачу пользователя он решает и чем этот продукт отличается.

## 4. Архитектура

Гибрид: **общая, но гибкая дизайн-система + свободная компоновка экранов агентом.**

```
одна фраза → бриф → спека → дизайн-система → экраны (агент) → критик ⟳ → сборка
```

| Детерминированно кодом | Агентом под ворота |
|---|---|
| `Info.plist` из `permissions[]` дословно | Композиция и вёрстка каждого экрана |
| Слой доступов на реальных iOS API | Контент: тексты, данные, состояния |
| Навигация из ролей экранов | Микровзаимодействия и анимации |
| Токены дизайн-системы | |

Дизайн-система **общая на все концепты, но гибкая**: концепт задаёт палитру, типографическую
шкалу и плотность, а не форкает компоненты. Агент компонует из неё свободно — он не выбирает из
списка готовых экранов.

## 5. Вход и роли

- **Разработчик пишет одну фразу** («соцсеть про образы из гардероба, набор vkontakte»).
- Из неё генерируется **бриф по простому шаблону** (аудитория, проблема, обещание, отличия,
  целевой набор доступов) → человек подтверждает или правит.
- **Весь контент пишет модель.** Никаких `content.domain.json` руками.
- Должно получаться **само за 1–2 итерации**.

## 6. Мимикрия и отстройка

- **Мимикрия — почти пиксель-в-пиксель** копия сервиса ВК. Фирменные цвета использовать можно.
  Источник правды — визуальный разбор реальных экранов ВК.
- **Отстройка — та же планка качества**, но ВК не копируем: собственная визуальная система.

## 7. Приёмка: агент-критик в цикле

После сборки — автоматический цикл, человеку показывается только прошедшее:

1. Скриншот **каждого** экрана и каждого состояния из симулятора.
2. Критик с квотой и адресом смотрит по трём осям:
   - **визуальные дефекты** — перекрытия, обрезания, отступы, контраст, хит-таргеты, иконки;
   - **соответствие эталону** — плотность, типографика, композиция против Revolut/Wise;
   - **продуктовая критика** — «этот экран вообще про идею продукта?»; шаблонный экран
     заворачивается, даже если он без багов.
3. Автоправка → пересборка → повтор, пока не чисто.

Оценку ставит тот, кто нашёл дефект, а не тот, кто его допустил.

## 8. Что с прежним

- `native/` v4 — **удалён**.
- HTML-контур — **закрывается**, как только новый пайплайн заработает.
- `concept.json` всех 26 концептов — **остаются**: это ценный актив и источник правды.
- Первый концепт на новом пайплайне — **«Образы» целиком**.
