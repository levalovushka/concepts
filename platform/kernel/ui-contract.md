# UI-контракт экрана

`uiContractVersion: 1` в `concept.json` включает строгую проверку всех экранов. Каждый экран объявляет:

- `pattern` — каноническую композицию;
- `purpose` — одну работу экрана для пользователя;
- `primaryAction` — точный видимый текст главного действия или `null` для системной поверхности;
- `states` — состояния, которые должны быть спроектированы.

## Паттерны

| Pattern | Когда использовать |
|---|---|
| `auth` | Вход, OTP, восстановление |
| `collection` | Корневая лента, каталог, библиотека |
| `detail` | Один объект и его действия |
| `task` | Линейная задача или мастер |
| `player` | Аудио- или видеовоспроизведение |
| `capture` | Камера, микрофон, сканер |
| `editor` | Форма, заметка, публикация |
| `settings` | Настройки и профиль |
| `state` | Loading, empty, soft/hard error, denied |
| `system` | PHPicker, Now Playing, lock screen, share sheet |

## Состояния

`default`, `empty`, `loading`, `error`, `denied`, `success`, `offline`. Не надо объявлять все: только те, которые реально меняют интерфейс. Отказ доступа — `denied`; сбой фичи — `error`: это разные состояния.

Сборка падает, если `primaryAction` не найдено в разметке. Так спека не может описывать несуществующую кнопку.
