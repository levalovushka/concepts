# UI-контракт экрана

`uiContractVersion: 2` в `concept.json` включает строгую проверку всех экранов по [`screen-recipes.json`](screen-recipes.json). Версия 1 остаётся совместимой для миграции старых концептов. Каждый экран объявляет:

- `pattern` — каноническую композицию;
- `purpose` — одну работу экрана для пользователя;
- `primaryAction` — точный видимый текст главного действия или `null` для системной поверхности;
- `states` — состояния, которые должны быть спроектированы.
- `density` — `low`, `medium` или `high`, если плотность разрешена выбранным рецептом;
- `contentCases` — минимум три реальных случая данных, включая крайний.

`uiContractVersion: 3` добавляет:

- `navigation` — роль экрана: `root`, `push`, `modal`, `fullscreen`, `system`;
- `hierarchy.primary/secondary` — что визуально первое и второе;
- объектные `contentCases` с обязательными `typical`, `stress`, `failure`;
- ровно один `data-primary` для заявленного главного действия;
- единый tab bar на всех root-экранах и отсутствие tab bar на дочерних;
- anti-slop lint: без inline-style, emoji-ассетов, `.ph` и безымянных icon-only controls;
- icon policy: концепты мимикрии используют единый Lucide sprite, нативная отстройка — SF Pro + SF Symbols; смешение допускается только целиком через reference profile (см. `iconography.md`).

## Паттерны

| Pattern | Когда использовать |
|---|---|
| `auth` | Вход, OTP, восстановление |
| `collection` | Корневая лента, каталог, библиотека |
| `detail` | Один объект и его действия |
| `task` | Линейная задача или мастер |
| `player` | Аудио- или видеовоспроизведение |
| `capture` | Камера, микрофон, сканер |
| `editor` | Форма, заметка, публикация |
| `settings` | Настройки и профиль |
| `state` | Loading, empty, soft/hard error, denied |
| `system` | PHPicker, Now Playing, lock screen, share sheet |

## Состояния

`default`, `empty`, `loading`, `error`, `denied`, `success`, `offline`. Не надо объявлять все: только те, которые реально меняют интерфейс. Отказ доступа — `denied`; сбой фичи — `error`: это разные состояния.

Сборка падает, если `primaryAction` не найдено в разметке, обязательное состояние рецепта пропущено, плотность противоречит рецепту или экран проверен только на идеальном контенте. Так спека не может описывать несуществующую кнопку или устойчивость, которой в интерфейсе нет.
