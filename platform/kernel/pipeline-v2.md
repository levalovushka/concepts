# Пайплайн качества v3

Пайплайн строит концепт двумя связанными треками: продукт доказывает, **зачем** приложение существует, интерфейс — **как** пользователь получает обещанный результат. Полная отрисовка начинается только после зелёного вертикального среза.

Подробный машинный контракт готовности: [`quality-contract-v2.md`](quality-contract-v2.md).

## Ворота

1. **Стратегия:** мимикрия или отстройка, целевой набор и профиль референса.
2. **Дивергенция:** 10–12 идей из разных продуктовых механизмов, а не оттенки одной темы.
3. **Отбор:** естественность доступов, сила проблемы, повторное использование, категорийность, отличие, UI-потенциал и реализуемость.
4. **Доказательство продукта:** аудитория, ситуация, проблема, обещание, core loop, три причины вернуться и non-goals.
5. **Вертикальный срез:** три разных экрана `entry → action → result`. До его ручной приёмки полная IA не строится.
6. **Позиционирование:** для мимикрии — `reference pattern → screen → observable behavior`, обязательные navigation roles и инварианты архетипа. Название паттерна без поведения не считается.
7. **Экранные рецепты v3:** purpose, navigation role, hierarchy, одно размеченное primary action и `typical / stress / failure` cases.
8. **Полная сборка:** только после принятого среза; root tabs проектируются один раз, push/fullscreen получают отдельные правила.
9. **Независимая критика:** product critique и минимум два визуальных прохода сохраняются в `readiness`, а не существуют только в отчёте агента.
10. **Автоприёмка:** anti-slop lint, геометрический audit, сценарии разрешений и повторный полный check.

## Быстрая проверка

`node scripts/build.mjs <slug>` разрешён для черновика. `npm run proof -- <slug>` и `npm run check` падают до браузерных тестов, если readiness не закрыт.

## Принцип миграции

Старые концепты остаются совместимыми с `qualityContractVersion: 1` и UI legacy/v2. Новый scaffold создаёт `qualityContractVersion: 2` и `uiContractVersion: 3`; понизить версию ради прохождения ворот нельзя.
