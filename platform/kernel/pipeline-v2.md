# Пайплайн качества v2

Пайплайн строит концепт двумя связанными треками: продукт доказывает, **зачем** приложение существует, интерфейс — **как** пользователь получает обещанный результат. Полная отрисовка начинается только после зелёного вертикального среза.

## Ворота

1. **Стратегия:** мимикрия или отстройка, целевой набор и профиль референса.
2. **Дивергенция:** 10–12 идей из разных продуктовых механизмов, а не оттенки одной темы.
3. **Отбор:** естественность доступов, сила проблемы, повторное использование, категорийность, отличие, UI-потенциал и реализуемость.
4. **Доказательство продукта:** аудитория, ситуация, проблема, обещание, core loop, три причины вернуться и non-goals.
5. **Вертикальный срез:** три разных экрана `entry → action → result`. Если ценность на них не читается, полная IA не строится.
6. **Позиционирование:** три знакомых паттерна, три отличия и минимум три экрана-доказательства. Для мимикрии — паттерны из `archetypes/`.
7. **Экранные рецепты:** purpose, primary action, states, density и три content cases на экран.
8. **Сборка и критика:** сначала срез, затем все состояния, визуальный аудит, сценарии и сверка слоёв.

## Быстрая проверка

`npm run proof` падает до браузерных тестов, если продуктовые ворота не пройдены. `npm run check` начинает полный цикл с этой проверки.

## Принцип миграции

Старые концепты могут оставаться на legacy UI-контракте, но продуктовые ворота обязательны для всех. Новые концепты создаются с `qualityContractVersion: 1` и `uiContractVersion: 2`.
