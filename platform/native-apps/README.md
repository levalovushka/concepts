# Приложения концептов

Концепт сначала доказывается в HTML по `PLAYBOOK.md`. После зелёного
`npm run review -- <slug>` он собирается в приложение на SwiftUI — руками.

```bash
npm run app -- <slug>       # Xcode-проект: Info.plist, entitlements, pbxproj
npm run app:run -- <slug>   # собрать, поставить в симулятор, запустить
```

Нужен macOS с Xcode 26 и симулятором `iPhone 17 Pro` (другой — через `CAMO_DEVICE`).

## Порядок работы

Читать **до** того, как писать код:

1. `concepts/<slug>/concept.json` — граф экранов и набор доступов: для каждого
   доступа жест, экран, цель при разрешении, fallback при отказе;
2. `docs/01-product-vision.md` — что здесь продукт, а что украшение;
3. `docs/03-design-system.md` — направление, токены и **чего избегать**;
   у «Двора» там прямо написано: без large title, без segmented control, без
   капсульных кнопок, без разделителей внутри карточки;
4. `assets/screenshots/<screen>.png` — визуальный эталон конкретного экрана.

Писать в `native-apps/<slug>/Sources/`. Дальше цикл: собрать → снять экран →
сравнить с эталонным PNG → починить.

Ветку отказа и ветку разрешения проходить launch-аргументами: системный промпт
живёт в SpringBoard и не нажимается инъекцией тапа.

```bash
npm run app:run -- <slug> -deny:location
npm run app:run -- <slug> -grant:camera,mic
```

## Что не пишется руками

Только то, где нет решений, а есть точность:

- **Info.plist** — ключи из набора доступов, `alert.text` концепта становится
  usage description: той строкой, которую видит пользователь в системном промпте
  и читает ревьюер App Store;
- **`.entitlements`**, фоновые режимы, `BGTaskSchedulerPermittedIdentifiers`;
- **Xcode-проект** и схема.

Всё это выводится из `concept.json` командой `npm run app`. Опечатка в
`com.apple.developer.usernotifications.communication` — это не «некрасиво», это
молча несобирающийся бандл, поэтому такие вещи не переписывают вручную.

Ещё общий `native-runtime/AccessRuntime.swift` — реальные запросы доступов,
цепочки и журнал. В нём нет ни одного дизайнерского решения.

## Что пишется руками — всё остальное

Токены, компоненты, раскладки, навигация, композиция каждого экрана и его
содержимое.

Общего кита компонентов **нет намеренно**: у «Двора» плотный список на серой
странице, у «Такта» тёмный плеер, у «Птиц» полевой справочник. Кит навязал бы
всем язык одного концепта.

Генератора экранов тоже нет — пробовали дважды. Композиция живёт в CSS, а не в
разметке: один и тот же `.ph` — это круглый аватар 28pt и полноэкранный герой,
по DOM их не различить. Автоматический перенос давал рейл сторис четырьмя
огромными карточками и список чатов сеткой серых квадратов. Скаффолд экранов
оказался не лучше: он не угадывал, но якорил — правишь заглушку вместо того,
чтобы проектировать экран, и получаешь генерик-вид.

## Что не переносится из концепта

У HTML-концепта есть **обвязка страницы** вокруг устройства: журнал доступов,
матрица доступов, список прототипов, ссылки на доки. Это инструменты
презентации, они живут в `kernel/page.html`. В приложение переносится только то,
что лежит в `screens/*.html`.

Проверка: показали бы вы это пользователю в App Store? Строка
`NSPhotoLibraryUsageDescription` на экране настроек — нет. Журнал фоновой задачи
на экране `background` — да, он есть в `screens/background.html` и показывает
результат entitlement'а.

Инструментарий, нужный для приёмки, уходит в консоль: рантайм печатает каждый
запрос строкой `[access] granted camera · NSCameraUsageDescription · problem`.
