# Платформа концептов

Ядро одно, концептов много. Продуктовая логика каждого концепта живёт в `concept.json` — из него собирается прототип, генерируются таблицы в доках и выводятся проверки. Один источник правды вместо четырёх копий одних данных.

Как придумывать концепт — в [PLAYBOOK.md](../PLAYBOOK.md) в корне репозитория. Здесь — как его собрать.

---

## Быстрый старт

Один раз на машину — зависимости и браузер для playwright:

```bash
npm install && npx playwright install chromium
```

Дальше цикл концепта:

```bash
node scripts/new-concept.mjs muzloop "Музлуп" vk-music
# заполнить concept.json и screens/*.html по PLAYBOOK.md
node scripts/build.mjs muzloop
node scripts/capture.mjs muzloop
node scripts/build.mjs muzloop        # ещё раз: свежие PNG нужны внутри dist
node scripts/test-flows.mjs muzloop
node scripts/lint-concept.mjs muzloop
```

Скаффолд из `_template` собирается и проходит тест сразу, до всякого заполнения — можно убедиться, что окружение живое, прежде чем что-то писать.

`test-flows.mjs`, `lint-concept.mjs` и `gen-docs.mjs` без слага проходят по всем концептам. `build.mjs` требует слаг (все концепты сразу — это `build-all.mjs`), `capture.mjs` тоже, но принимает после слага список id экранов, чтобы перерисовать не всё. Те же шаги через npm-скрипты: `npm run build -- <slug>`, `build:all`, `shots`, `test`, `lint`, `docs`, `new`.

## Контракт экрана

Экран — файл `screens/<id>.html`, `id` должен быть в `concept.json`.

| Атрибут | Значение |
|---|---|
| `data-go="<id>"` | переход на экран |
| `data-back` | назад по стеку |
| `data-jump="<id>"` | уйти с оверлея, не складывая его в историю |
| `data-ask="<ключи>\|<при разрешении>\|<при отказе>"` | запрос доступа; цепочка алертов подряд — через `+`: `speech+mic` |
| `data-activate="<ключ>\|<экран>"` | entitlement: granted без системного алерта |
| `data-toast="<текст>\|<экран>"` | снекбар; экран во второй части необязателен |
| `data-show-denied="<ключи>"` | показать при отказе; несколько ключей — через запятую |
| `data-hide-denied="<ключи>"` | скрыть при отказе |
| `data-show-granted="<ключ>"` | показать только при разрешении |
| `data-switch="<ключ>"` | свитч отражает статус доступа |

Два правила, которые проверяет тест:

1. **Fallback лежит там, куда приводит отказ.** Если `data-ask="location|yarn|project"`, то видимый `data-show-denied="location"` должен быть на `project` — иначе пользователь после отказа не увидит ничего.
2. **Проверяется каждый триггер доступа, а не первый.** Один ключ часто просят с нескольких экранов; fallback нужен на каждом.

## Карта экранов

Из этих же атрибутов выводится карта: дерево IA в панель «Информационная архитектура» на Overview и таблица «Экран → действие → цель → доступ» в раздел «Документы». Плюс блоки `@generated:ia-tree` и `@generated:transitions` в `docs/02-architecture.md` — `node scripts/gen-docs.mjs <slug>`.

Руками карту не рисуем: рукописная схема расходится с прототипом на первой же правке. Подпись действия — `aria-label` элемента или его первая текстовая строка, так что осмысленный `aria-label` на составных строках списка сразу улучшает карту.

## Что валидируется автоматически

**Спека** (`lib.mjs`, падает при сборке): `slug` не совпадает с папкой · экран без `id`/`title` · дубли экранов и ключей · несуществующий стартовый экран · несуществующий `parent` и цикл в цепочке родителей · вкладка без экрана · доступ без `alert.title`/`alert.text`, без `feature` или без `fallback` · ссылка на несуществующий экран или `target` · условный доступ без `requires` · отсутствие файла разметки для экрана спеки.

**Карта** (`screen-map.mjs`, падает при сборке): переход в экран вне спеки · экран, недостижимый из `start` по всем переходам, включая ветки отказа · отказ, ведущий на экран без `data-show-denied` для этого ключа.

**Прототип** (`test-flows.mjs`): старт с нужного экрана, без промптов и с пустым журналом · все экраны спеки есть в разметке · все доступы достижимы из UI · в разметке нет доступов вне спеки · нет битых переходов · entitlement срабатывает без системного алерта · отказ по каждому триггеру ведёт на видимый fallback · цепочки алертов · отказ на первом шаге не спрашивает второй · повторный вход без алерта · `data-back` возвращает к `parent` из спеки · хит-таргеты ≥ 44pt · чистая консоль.

**Слои** (`lint-concept.mjs`): спека ↔ разметка (экраны в обе стороны, прототипы собраны, каждый `plist` попал в файл) · битые ссылки и отсутствующие файлы доков · мёртвые классы в `styles.css` · классы без стиля · карточка App Store (блок есть, лимиты Name / Subtitle / Promotional Text / Keywords 30 / 30 / 170 / 100, пробел после запятой в keywords, дубли слов из Name/Subtitle, `reviewAccount.phone`, сходимость ATT в наборе и трекинга в privacy-лейблах) · коллизии имён классов с ядром · неиспользуемые ассеты `assets/media` · следы других концептов · сходимость чисел. Ядро линтуется отдельно (`--kernel`): класс или токен мёртв, только если его не использует ни один собранный концепт.

## Деплой

Один сайт Netlify, концепты по подпутям: `/dvor/`, `/petlya/`, `/primer/`, `/rasklad/`, `/shellac/`, `/rehearsal/`, `/ptitsy/`, `/radius/`, `/liga/`, `/strochka/`, в корне — галерея. `netlify.toml` в корне репозитория уже настроен: `base = platform`, команда `npm run build:all`, публикуется `dist`.
