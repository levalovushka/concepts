UI

32 экрана: четыре корня вкладок, карточки смены и человека, шиты отметки и записи, системные поверхности (камера, локскрин, CallKit, Face ID, Safari, экран «Домой»). Статусы доступов не хранит — только отображает.

Domain

Точка · Смена · Отметка · Подмена и отклик · Человек и общие смены · Брифинг с расшифровкой · Акт передачи · Ставка и период.

Services

Permissions · PhoneAuth (SDK провайдера) · Timesheet (SSID ↔ карточка точки) · Nearby (MKLocalSearch, MKDirections) · ScheduleOCR (PHAsset + Vision) · Briefing (AVAudioRecorder, SFSpeechRecognizer, AVAudioSession) · Calls (PushKit + CallKit) · Notifications (FCM + NSE) · Refresh (BGAppRefreshTask) · Credentials (Keychain + AutoFill).

Data

CoreData — табель, часы, акты, ставки. Keychain общей группы — токен входа и логины точек. App Group group.app.peresmenka — снапшот для виджета и аватары для Notification Service Extension. Firestore и Storage через SDK: смены, отклики, переписка, файлы брифингов. Своего бэкенда нет.

External

SDK входа по номеру · Firebase (Firestore, Storage, Cloud Messaging) · SDK звонков (LiveKit / Agora) · рекламный SDK · карты Apple. Serverless-правила — конфигурация, не серверный код.

Правило, которое важнее таблицы. До каждой фичи ревьюер должен дойти сам за 2–3 тапа без инструкции. Фича, которая в сборке есть, но спрятана, по последствиям равна её отсутствию.

Что не заявлено. com.apple.developer.associated-domains: диплинков в концептах не делаем — не проектируем, не рисуем, ключ не заявляем. Он остаётся неотработанным, решение по нему принимает человек.

Почему здесь нет бэкенда

Что потребовало бы сервера и чем это заменено на клиенте. Граница простая: BaaS-SDK и security rules — конфигурация, а строка, требующая написать и развернуть свой обработчик, — повод переделать фичу.
