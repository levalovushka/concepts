# Праймер — дизайн-система

Системный хром берётся из ядра (`kernel/base.css`, канон — `kernel/ios-chrome.md`, стенд — `components.html`). Здесь только то, что добавляет концепт.

## Один акцент и почему он холодный

| Токен | Значение | Где |
|---|---|---|
| `--accent` / `--accent-fill` | `#2b6b8f` | светлая тема, все интерактивные элементы |
| `--accent` в тёмной теме | `#6ac6ee` | документ в тёмной теме |
| `--pm-tint` | `#6ac6ee` | иммерсивные экраны концепта: `#2b6b8f` на `#15171a` не читается |

Акцент выбран холодным **намеренно**. На экране почти всегда есть свотчи красок — коричневые, охристые, оливковые. Тёплый акцент начал бы с ними спорить за главность, и пользователь перестал бы отличать «цвет краски» от «цвет интерфейса». Холодный синий не встречается в палитре миниатюры и поэтому читается как служебный.

## Поверхности

| Тип | Цвет | Экраны |
|---|---|---|
| Иммерсивная | `#15171a` | `lesson`, `dropper` |
| Камера | `#000` + `.ph.on-dark` вместо превью | `scan` |
| Локскрин | градиент `#16283a → #0d1620 → #14100f` | `background` |
| Grouped светлая | `#f2f2f7` + карточки `#fff` | `lessons`, `projects`, `project`, `paint`, `scanfail`, `dropfail`, `settings`, `steps` (sheet) |
| Белая | `#fff` | `phone`, `code`, `gallery` |

Правило статус-бара: `light: true` в `concept.json` → движок ставит `.status.dark-ink`. Иммерсивные экраны — `light: false`, чернила белые.

## Три ловушки CSS — как они обойдены здесь

1. **Коллизия имён с ядром.** Все свои классы с префиксом `pm-`. Компаунды вида `.pm-sw.sm`, `.state .t-subhead`, `.pm-hero .pill` — это расширение ядра, а не объявление с нуля, и линтер их не считает коллизией.
2. **Шорткат `background` сбрасывает `background-image`.** В `styles.css` его нет ни разу: только `background-color`, а для градиентов — `background-image`. Иначе `.ph` теряла бы серую подложку, а `.prog i` — заливку.
3. **Шорткат `margin` глушит утилиты `.mt*` из ядра.** `styles.css` подключается после `base.css`, поэтому `margin: 0` в своём классе побеждает `.mt8`. Везде только `margin-top` / `margin-bottom` по отдельности, и ни один класс, комбинируемый с `.mt*`, не задаёт `margin-top`.

## Медиа: только данные

Фотографий и иллюстраций в концепте нет. Всё, что по макету было бы снимком, — плейсхолдер `.ph` (`.ph.on-dark` на тёмном): обложка курса, миниатюра проекта, превью камеры, сетка PHPicker, само фото под пипеткой.

Кодом (`media.mjs`, детерминированный seed, без `Math.random`) рисуются три файла — содержимое, без которого фича непонятна:

| Файл | Что это | Где |
|---|---|---|
| `wave.svg` | Волновая форма дорожки: пройденная часть в акценте | `lesson` |
| `barcode.svg` | Этикетка баночки с **настоящим EAN-13**: таблицы L/G/R, паритет по первой цифре, контрольная цифра | `scan` |
| `recipe.svg` | Пропорции замеса площадью блоков; ink внутри блока выбирается по светлоте подложки | `paint` |

`recipe.svg` рисуется 1:1 под ширину контента (343 pt): при масштабировании подписи уехали бы ниже читаемых 11 pt. Названия красок вынесены строкой в разметку — в картинке остались только площади и части.

**Дизайнерская тонкость пипетки.** Само фото — серый плейсхолдер, поэтому результат работы инструмента показан рядом: ряд снятых свотчей с HEX и список «чем это красить из ваших паков» с ΔE. Без этого экран выглядел бы как пустая рамка с лупой.

## Геометрия

375 × 812, radius устройства 32, safe areas 47 / 34, контентный отступ 16, хит-таргет ≥ 44 (утилита `.tap`), строка списка ≥ 44. Радиусы концепта: 8 (свотч), 10–12 (обложки и превью), 14 (карточки и чипы), 22 (Now Playing).
