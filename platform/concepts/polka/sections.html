Социальная сеть коллекционеров, где разговор не теряется в ленте: принятое уточнение меняет карточку физического предмета и сохраняет автора правки.

УТП. Показать находку за минуту, разобрать её знакомым кругом и оставить проверенную атрибуцию рядом с вещью.

Карточка предмета

Категория, год, происхождение, состояние, статус и история правок.

Знакомый круг

Лента, клубы, обсуждения, сообщения, голосовые и звонки.

Живые поводы

Истории владельцев, видеообзоры, ярмарки и список поиска.

Клиентское приложение: своего бэкенда нет, PermissionsService — единственная точка запроса доступов. Ниже — пути, по которым пойдёт ревьюер: каждый упирается в фичу, а не в объяснение.

Телефон→Код из SMS→Лента находок
Лента→Новая находка→Камера / Фото→Карточка предмета
Профиль→Ярмарка→В пути сегодня
Истории→Видеообзоры→Телевизор

UI

Экраны, tab bar, nav stack, system ask, snackbar. Только отображение — статусы доступов не хранит.

Domain

ItemCard · AttributionRevision · Collection · Club · Fair · ExchangeIntent · Story.

Services

Permissions · PhoneAuth · MediaPicker · Messaging/VoIP · MapKit · Cast discovery · Notifications.

Data

CoreData — своё. Keychain — токен входа. FileManager — файлы пользователя. Статический контент-пак только на чтение. Своего бэкенда нет.

External

CDN контент-пака · SDK входа по номеру · остальные SDK, если они реально в сборке.

{{PERM_MATRIX}}

Правило, которое важнее таблицы. До каждой фичи ревьюер должен дойти сам за 2–3 тапа без инструкции. Фича, которая в сборке есть, но спрятана, по последствиям равна её отсутствию.

Почему здесь нет своего бэкенда

Лента, storage и вход делегированы BaaS; звонки — VoIP-провайдеру; карты — MapKit; демо работает на локальном snapshot. В репозитории нет собственного API или серверной бизнес-логики.
