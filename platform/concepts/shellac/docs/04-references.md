# Шеллак — референсы и review notes

## Что показать ревьюеру

Порядок, в котором фичи находятся сами, без инструкции:

1. **Стартовый экран → «Найти пластинку».** Первая строка «Архива», один тап до промпта камеры. Это главная функция продукта.
2. **Затвор → «Совпадение».** Видно, что именно прочитано с этикетки: лейбл, название, матрица, год. Рядом — найденная в архиве сторона.
3. **«Поставить сторону A» → плеер → «Слушать при погасшем экране».** Блокируем экран: сторона продолжает играть, Now Playing заполнен, кнопки на локскрине управляют этим же воспроизведением.
4. **Профиль.** Четыре строки — уведомления, две ссылки, звук в фоне — каждая ведёт к своей фиче.

## Review notes по доступам

**`NSCameraUsageDescription`.** Камера — главная функция приложения: пользователь наводит её на этикетку шеллачной пластинки, приложение читает лейбл, название и матричный номер и находит эту сторону в архиве. Распознавание идёт на устройстве (`DataScannerViewController`, `VNRecognizeTextRequest`), кадр не сохраняется и никуда не отправляется. Совпадение ищется в локальном индексе контент-пака.

**`NSPhotoLibraryUsageDescription`.** Два применения. Первое — распознать пластинку по уже сделанному снимку этикетки (тот же on-device OCR). Второе — приложить фото конверта к экземпляру на своей полке: коллекционеры описывают состояние, и фото конверта — часть описания. Выбор идёт через `PHPicker`, приложение получает только отмеченный снимок и не имеет полного доступа к медиатеке.

**`UIBackgroundModes: audio`.** Сторона шеллачной пластинки на 78 оборотов играет около трёх минут, отдельных дорожек внутри нет, перемотки вперёд в приложении нет. Единственный способ её слушать — поставить и убрать телефон. Реализовано: `AVAudioSession` категории `.playback`, `MPNowPlayingInfoCenter` с обложкой, стороной, лейблом и длительностью, `MPRemoteCommandCenter` с play / pause / следующая и предыдущая сторона. **Приложить видео:** запись стороны, блокировка экрана, работающие кнопки на локскрине, сторона доигрывает до конца.

**`aps-environment`.** Единственный тип уведомления — «пластинка из вашего „Розыска“ оцифрована и появилась в архиве». «Розыск» — локальный список матричных номеров, которых в паке пока нет; он пополняется сканером и ссылками. Регистрация в APNs через SDK провайдера, отправка из дашборда архива. Уведомление приходит при пополнении пака, а не по расписанию.

**`com.apple.developer.associated-domains`.** Заявлен один домен — `shellac.app`, только `applinks`, два пути:

- `/rec/<матрица>` — открывает конкретную сторону каталога в приложении. Так коллекционеры обмениваются находками.
- `/want?m=<матрица>` — кладёт матричный номер в локальный «Розыск». Из ссылки берётся только номер из query; страница-источник не запрашивается, её разметка не читается, ничего оттуда не скачивается.

`webcredentials` **не заявлен**: в приложении нет входа и нет учётных записей. Файл `apple-app-site-association` статический, лежит на своём домене.

## Права на записи

В контент-пак попадают только записи в общественном достоянии — шеллачные пластинки, изданные до 1929 года. Права проверяются при сборке пака (оффлайн, до выпуска), а не в приложении. Приложение каталог только читает: загрузки пользовательского контента, публикации и обмена файлами в нём нет.

Все изображения в приложении — обложки, конверты, этикетки, сцены — **сгенерированы кодом** (`media.mjs`). Стоковых фотографий и сканов настоящих этикеток в сборке нет. Названия лейблов на этикетках вымышленные: приложение не изображает существующую фирму.

## Гайдлайны, под которые концепт специально не попадает

| Guideline | За что | Чем закрыто |
|---|---|---|
| 4.2 Minimum Functionality | Тонкая обёртка без своей ценности | Сканер физического носителя + свой индекс матричных номеров + полка с состоянием экземпляров. Тест на подмену пройден: без якорей остаётся папка mp3 |
| 4.3 Spam | Клон существующего приложения | Не стриминг: нет чартов, плейлистов, подписки, рекомендаций, соцграфа и новинок. Закрытый корпус записей до 1929 года |
| 2.3.1 Hidden features | Недостижимая функциональность | Главная фича — первая строка стартового экрана. Остальные — не глубже двух тапов |
| 5.1.1 Data & privacy | Доступ есть, фичи нет | У каждого доступа фича с точным жестом и рабочим fallback. Распознавание on-device, снимки не сохраняются |
| 2.5.4 Background modes | Неоправданный фоновый режим | Реальный playback, заполненный Now Playing, обработанные remote-команды. Других фоновых режимов не заявлено |
| 3.1.1 IAP | Цифровой контент мимо StoreKit | Внутри ничего не продаётся: пак бесплатный, покупок нет |

## Чего в наборе намеренно нет

- **ATT / `NSUserTrackingUsageDescription`** — рекламы в приложении нет, IDFA никуда не уходит. Заявлять доступ было бы пустым.
- **Геопозиция** — приложение не ищет магазины и не привязывает находки к месту. Фичи нет — доступа нет.
- **Микрофон** — распознавание идёт по этикетке, а не по звуку. Пластинка в руках молчит.
- **Локальная сеть / Cast** — сторона слушается в наушниках или в колонке по AirPlay, для которой доступ не нужен.
- **`webcredentials`** — нет входа.

## Референсы

- **Great 78 Project** (Internet Archive) — как выглядит корпус оцифрованного шеллака и какие метаданные у него есть: матрица, лейбл, год, состояние экземпляра.
- **Discogs** — модель «релиз ↔ экземпляр»: одна и та же запись существует в разных экземплярах с разным состоянием. Отсюда разделение «запись в архиве» и «экземпляр на полке».
- **Каталоги 1910–1920-х** — раскладка этикетки: лейбл дугой сверху, название над отверстием, исполнитель под ним, матрица снизу.
- **Apple Music, экран Now Playing** — источник поведения фонового аудио и remote-команд, не визуальный референс.
- **`DataScannerViewController`** (VisionKit) — живое распознавание текста в кадре с рамкой и подсветкой найденного.
