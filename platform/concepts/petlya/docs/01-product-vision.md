# Петля — продуктовый вижен

**Однострочник:** уроки вязания, которые можно смотреть, когда руки заняты спицами.

---

## Позиционирование и УТП

**Петля** — iOS-приложение школы вязания. Не «видеоплеер с уроками», а мастерская: урок, схема, счётчик рядов и дневник проекта в одном месте.

Весь продукт вырастает из одного физического ограничения: **во время вязания руки заняты, и телефон в них не держат.** Нельзя ткнуть в паузу, нельзя вглядываться в маленький экран, нельзя отметить ряд в приложении. Отсюда четыре решения, которые и есть продукт:

1. **Урок уходит на телевизор** — телефон некуда положить, а ТВ в комнате уже есть.
2. **Голос ведёт при погасшем экране** — инструкция звучит, глаза на спицах, перемотка с наушников.
3. **Схема лежит под видео** — не отдельным приложением и не распечаткой, а вторым слоем того же экрана.
4. **Ряды считаются голосом** — сказал «ряд», счётчик прибавил. Спицы из рук не выпускаются.

| | YouTube / соцсети | **Петля** |
|---|---|---|
| Формат | Ролик, который смотрят | Урок, под который **делают** |
| Схема | Отдельная распечатка или PDF | Второй слой урока, идёт синхронно |
| Счёт рядов | Бумажка, кликер, память | Голосом, без рук |
| Прогресс | Нигде | Дневник проекта с заметками к таймкоду |
| Материалы | Нигде | Скан этикетки: состав, метраж, **номер партии** |

**Бренд:** `Петля.` + teal `#0d8a7a`.

## Целевая аудитория

**Ядро:** ученицы и ученики конкретной школы вязания — те, кто уже взял курс и вяжет по нему дома. Возраст широкий, 25–60. Телефон под рукой, руки заняты, рядом телевизор.

**Вторичная:** самоучки среднего уровня, которые вяжут по схемам и страдают от счёта рядов и подбора партии пряжи.

**Не целевая в v1:** маркетплейс схем, соцсеть вязальщиц, продажа пряжи, профессиональные дизайнеры.

## Ключевые продуктовые принципы

1. Руки заняты — интерфейс не требует рук там, где может обойтись.
2. Схема и видео — одно, а не два.
3. Прогресс живёт в проекте, а не в голове.
4. После загрузки урока приложение работает без сети.
5. Каждый доступ стоит за фичей, до которой видно как дойти.
6. Вход по номеру опознаёт владельца курса — и только. Ни ленты, ни чужих данных, ни модерации.
7. Своего бэкенда нет и не должно появиться.

## Ключевые пользовательские сценарии

1. **Первый запуск:** номер телефона → код из SMS → каталог курсов. Дальше приложение работает без сети.
2. **Вечер с вязанием:** урок → «Смотреть на ТВ» → телефон рядом работает счётчиком.
3. **Руки в работе:** «Считать голосом» → говорит «ряд» после каждого ряда, экран не трогает.
4. **Экран погас:** голос урока продолжает вести, перемотка ±15 сек с наушников.
5. **Сверка со схемой:** вышел в «Файлы» за PDF выкройки — урок ушёл в PiP и не прервался.
6. **Заметка на будущее:** «на 4:12 убавка не сошлась» плюс фото своего результата — в проект.
7. **Кончилась пряжа:** карточка проекта → «Магазины пряжи рядом» → четыре магазина на карте, куда можно съездить.
8. **Новый моток:** скан этикетки → состав, метраж и партия сами попали в проект.
9. **Этикетка мятая:** скан не сработал → экран объясняет почему и предлагает те же поля вручную — партия всё равно попадает в проект.
10. **Свой приём:** телефон на штативе над руками → запись со звуком → осталась в проекте.

## Почему здесь нет бэкенда

Приложение однопользовательское. Вход по номеру опознаёт владельца курса и держится на SDK провайдера — своего сервера нет. Ни ленты чужого контента, ни модерации.

|---|---|
| Каталог уроков и видео | Контент-пак: `lessons.json` + mp4 статикой на CDN. Только чтение |
| Опциональные вход и регистрация по номеру телефона | SDK провайдера аутентификации, пароль и токен сессии в Keychain |
| Профили, подписки, лайки | Вырезаны. Вход только опознаёт устройство — ни ленты, ни UGC, ни модерации |
| Комментарии | Заметки к таймкоду, локально в CoreData |
| Прямые эфиры | Вырезаны. Вместо них — локальная запись своего ракурса |
| Push через APNs | SDK провайдера (OneSignal / FCM), отправка из дашборда школы |

| Распознавание речи и этикетки | `SFSpeechRecognizer` on-device + `DataScannerViewController`; не распозналось — форма ручного ввода |

Хостинг сводится к раздаче статики. Серверного кода — ноль.

## Модель монетизации

- Курс продаётся школой вне приложения; приложение — способ его проходить.
- Между уроками — реклама через ad SDK. С разрешением ATT она по интересам, без — обычная.
- Нет в v1: подписка внутри приложения, маркетплейс схем, продажа пряжи.

---

## Что НЕ делаем в v1

Лента чужого контента · комментарии и соцграф · прямые эфиры · маркетплейс схем · редактор схем · собственный бэкенд · Always-геолокация · background modes сверх `audio`.

## Критерии успеха концепта

1. Вход занимает два экрана и не спрашивает ничего, кроме номера.
2. УТП понятно за 5 секунд на первом экране каталога.
3. До каждой фичи, стоящей за доступом, ревьюер доходит сам за 2–3 тапа.
4. У каждого отказа в доступе есть работающий fallback, а не заглушка.
5. Голосовой счётчик работает без сети — это проверяемое обещание.
6. Cast, фоновый звук и PiP лежат в уроке, а не спрятаны в настройках.
7. Тест на подмену: убрать Cast, фон и голосовой счётчик — останется обычный видеоплеер. Значит, они и есть продукт.
