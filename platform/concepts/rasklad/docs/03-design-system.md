# Расклад — дизайн-система и токены

Системный хром не изобретается: статус-бар, нав-бар, таб-бар, списки, свитчи, алерты и снекбар берутся из ядра (`kernel/base.css`, канон — `kernel/ios-chrome.md`, сторибук — `components.html`). Здесь только то, что добавляет концепт.

---

## Поверхности

| Поверхность | Где | Чем задана |
|---|---|---|
| Grouped светлая | «Сегодня», «Колода», «Дневник», «Запись», «Карты колоды», «Номер карты», «Профиль», вход | `#f2f2f7` + `.ios-list` карточками |
| Иммерсивная тёмная | «Размышление», локскрин | градиент от `#1a2438` к `#0a0d14`, текст белый |
| Системная камера | «Скан карты» | `.cam` из ядра, превью — плейсхолдер `.ph.on-dark` |
| Системный пикер | «Фото» | сетка `.rk-pgrid` из плейсхолдеров, шапка «Отмена / Добавить» |

Вечер задаёт направление: светлые экраны — то, что делают глазами, тёмные — то, что делают с закрытыми глазами. Переход между ними всегда один и тот же жест: «Слушать» → плеер → «Погасить экран».

## Токены

| Токен | Значение | Где |
|---|---|---|
| `--accent` | `#3a5a8c` (тёмная тема — `#93b4e6`) | единственный акцент: CTA, номера карт, активная вкладка |
| `--accent-fill` | `#3a5a8c` | заливки и текст на светлом |
| `--device-w` / `--device-h` | 375 / 812 | iPhone X-class |
| `--safe-top` / `--safe-bottom` | 47 / 34 | все оверлеи считаются от токенов |
| `--margin` | 16 | контентные поля |
| `--face` | Geist 400–700 | интерфейс |
| `--mono` | Geist Mono 400–500 | номера карт, таймкоды, длительности, счётчики |
| `--r-panel` / `--r-card` | 12 / 10 | панели документа |

Мono — только для данных: номер карты (`07`), таймкод (`3:12`), длительность (`11:00`), счётчики серии. Всё остальное — Geist.

## Компоненты концепта (`styles.css`, префикс `rk-`)

| Класс | Что это |
|---|---|
| `.rk-col` | колонка экрана с прижатым к низу CTA; `flex:none` у детей обязателен |
| `.rk-pad` | стандартные поля прокручиваемого тела |
| `.rk-hero` | приглашение к практике на «Сегодня»: eyebrow, заголовок, CTA, вторичное действие |
| `.rk-second` | вторичное действие рядом с filled: plain accent во всю ширину |
| `.rk-panel` | белая панель под данные, нарисованные кодом |
| `.rk-series` / `.rk-stats` / `.rk-stat` | сетка вечеров и три числа под ней |
| `.rk-num` (`.lg`, `.is-new`) | номер карты — опознавательный знак вместо картинки |
| `.rk-dur` | длительность дорожки, mono |
| `.rk-cardtop` / `.rk-face` / `.rk-cardmeta` / `.rk-cardname` | карта: плейсхолдер аверса + номер и имя рядом |
| `.rk-q` / `.rk-qn` | вопрос вечера и его номер (текст в несколько строк, не обрезается) |
| `.rk-scanhint` / `.rk-scanwin` / `.rk-scanread` | подсказка, окно скана по центру кадра, результат чтения |
| `.rk-pl-*` | плеер: обложка-плейсхолдер, заголовок, время, транспорт |
| `.rk-cues` / `.rk-cue` | метки вопросов дорожки с таймкодами |
| `.rk-np-*` | карточка Now Playing на локскрине |
| `.rk-deckhead` / `.rk-deckcount` / `.rk-deckbar` / `.rk-legend` / `.rk-dot` | прогресс по колоде и легенда к нему |
| `.rk-snip` / `.rk-thumb` / `.rk-note` / `.rk-shot` | дневник: строка записи, метка фото, текст записи, место под снимок |
| `.rk-pgrid` / `.rk-pick` | системный PHPicker |
| `.rk-hintpanel` / `.rk-markerhint` | подсказка «где искать номер» на экране ручного ввода |

Все имена — с префиксом `rk-`, чтобы ни одно не столкнулось с ядром: класс, объявленный с нуля и там и здесь, молча ломает страницу (`styles.css` подключается после `base.css`). Единственные исключения — намеренные уточнения ядровых компонентов составным селектором: `.auth-mark.sm`, `.ph.is-picked`, `.rk-pgrid > .ph`.

### Три ловушки, которые здесь обойдены

1. **Коллизия имён с ядром** — все свои классы под `rk-`, проверяется линтером.
2. **`background` вместо `background-color`** — шорткат сбрасывает `background-image`, а его подставляет плейсхолдер `.ph`. В `styles.css` шортката `background` нет ни разу.
3. **`margin` вместо `margin-bottom` / `margin-top`** — шорткат глушит утилиты `.mt*` из ядра. В `styles.css` используются только односторонние свойства.

## Картинки и данные

**Картинок в концепте нет.** Везде, где по макету фотография, стоит плейсхолдер `.ph` — серое поле с иконкой камеры (`.ph.on-dark` на тёмной подложке):

| Где | Что было бы фотографией |
|---|---|
| «Карта» | аверс карты, 126×176 |
| «Размышление», локскрин | обложка дорожки |
| «Запись практики» | фото расклада на столе |
| «Фото» | сетка снимков медиатеки |
| «Скан карты» | превью камеры |

Аверс — серый прямоугольник, поэтому карту опознают **имя и номер рядом с ним**: `.rk-num.lg` + `.rk-cardname` стоят вплотную к плейсхолдеру, и на всех списках карта представлена номером, а не картинкой.

**Данные рисуются кодом** — `media.mjs`, чистые функции, детерминированный seed, никакого `Math.random`:

| Файл | Что показывает | Где используется |
|---|---|---|
| `wave.svg` | волновая форма дорожки, отыгранная часть акцентом | «Размышление» |
| `series.svg` | сетка вечеров практики за пять недель, серия — подряд | «Сегодня», «Дневник» |
| `deck.svg` | 44 карты колоды: пройденные, следующая, непройденные | «Колода» |
| `marker.svg` | цель сканирования: номер и точечная метка в углу карты | «Скан карты», «Номер карты» |

`marker.svg` — не украшение: это то, что читает камера. Метка детерминированно выводится из номера карты, поэтому «распознавание» в концепте означает чтение напечатанного кода, а не угадывание рисунка.

## Хит-таргеты и safe areas

Все интерактивные элементы — не меньше 44 pt: строки списка (`min-height:44`), `.btn-filled` (50), `.btn-tinted` (44), `.icon-btn` (44×44), вторичное действие `.rk-second` (44). Мелкие текстовые триггеры несут утилиту `.tap`, которая добивает область нажатия псевдоэлементом. Проверяется тестом, а не глазами.

Safe areas — только через `--safe-top` (47) и `--safe-bottom` (34): статус-бар, `.cam-top`, `.cam-bottom`, `.cta-col`, `.sheet-footer`. Хардкода `54px` в концепте нет.

На экранах **без таб-бара** прокручиваемое тело несёт `.rk-safe` = `margin-bottom:var(--safe-bottom)`: вьюпорт прокрутки кончается выше home indicator, поэтому строка не проезжает под ним ни при каком положении прокрутки. Именно `margin`, а не `padding`: padding убирает перекрытие только в конце прокрутки. На экранах с таб-баром это не нужно — таб-бар сам держит `padding-bottom:var(--safe-bottom)`, и тело прокрутки кончается на 70 pt выше индикатора.

Светлые экраны объявлены `light: true` в `concept.json` — движок включает `.dark-ink` на статус-баре. Тёмные (`scan`, `player`, `background`) остаются со светлыми чернилами.
