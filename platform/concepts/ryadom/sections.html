Знакомые люди из одного спортивного клуба публикуют тренировки, зовут на локальные маршруты и собираются по предметным сообществам.

Ограничение продукта. {{TAGLINE}}

Если убрать подтверждённый клуб, знакомых участников, темп, дистанцию и точку старта, останется обычная социальная лента. Эти связи — продукт, а не оформление.

{{FEAT_GRID}}

Знакомая социальная навигация ведёт к клубным объектам: публикации, предметные сообщества, тренировки, маршруты и профиль участника.

Лента клуба→Что нового?→камера / медиатека / место→пост тренировки
Сообщества→Бег · утренняя группа→6 км · темп 6:10→тренировка
Маршруты→Набережная 8 км→голосовой пейсинг→локскрин
Тренировка→Отмечать дорогу→кто в пути→точка старта

UI

Пять устойчивых вкладок, карточная лента, публичные карточки тренировок, предметные сообщества и профиль. Системные permission-поверхности остаются из ядра.

Domain

Клуб, участник, секция, публикация, тренировка, маршрут, отрезок и точка старта. Сообщество — секция реального клуба, не роль и не админская сущность.

Services

PermissionsService, PhoneAuth SDK, Core Location, AVFoundation, Photos, Contacts, APNs, BackgroundTasks, Bonjour/Cast и AVAudioSession.

Data

Локальные черновики, скачанные маршруты и индекс видео — Core Data / FileManager. Сессия расширений — Keychain group.

External

Лента и секции — Firestore с security rules; медиа — Storage; пуши — Cloud Messaging. Своего серверного обработчика нет.

Матрица доступов

Каждый ключ привязан к наблюдаемой клубной фиче и единственной точке запроса.

{{PERM_MATRIX}}

Не заявлено: associated domains. Концепт не проектирует диплинки; приглашение отправляет обычную веб-страницу клуба через системное меню.

Почему здесь нет своего бэкенда

Удалённые социальные данные обслуживаются SDK провайдера и его security rules; серверный код концепта не пишется.
