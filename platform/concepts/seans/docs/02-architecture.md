# Сеанс — карта экранов и архитектура

Блоки `@generated:*` пересобираются командой `npm run docs -- seans` — внутрь них руками не пишем.

22 экрана, четыре вкладки: **Главная · Клипы · Показы · Профиль**. Два первых экрана — вход по номеру, дальше единственный onboarding-экран (ATT), дальше корень «Главной». Своего бэкенда нет; половина сценария зала живёт внутри Wi-Fi площадки и без интернета работает целиком.

## Информационная архитектура

Дерево выведено из разметки экранов и `concept.json`: вложенность — по `parent`, подпись «открывается» — реальный элемент прототипа. Первые два узла всегда одни и те же: вход по номеру (`phone` → `code`).

## Почему здесь нет бэкенда

<!-- @generated:backendless -->
| Требовало бы сервера | Решение без сервера |
|---|---|
| Каталог фильмов и дорожек | Статический пак catalog.json + файлы на CDN, только чтение; фильмы — общественное достояние |

## Правила IA

**Показ — не вкладка, а карточка.** `session` лежит под «Главной», а не в отдельном разделе: показ существует один вечер, и заводить под него корень навигации значит держать пустую вкладку 27 дней в месяц. Из «Показов» и с площадки в ту же карточку ведут ссылки.

**Зал — стек из трёх экранов, а не один.** `session` (что за показ и как попасть) → `join` (что нашлось в сети и что слушать) → `hall` (вы внутри). Разделение не украшение: до входа в зал выбор дорожки — это решение, после входа — переключатель на ходу. На `join` показано, чего в зале уже не видно: адрес устройства, задержка, расхождение.

**Пульт показа доступен с двух сторон.** `curator` объявлен ребёнком `session` — так его находит гость, который сам ведёт вечер. Вторая точка входа — строка «Вы ведёте показ сегодня» в профиле. Возврат по `data-back` идёт к объявленному родителю, то есть к карточке показа.

**Что убирают fallback'и.** Отказ не оставляет данные, которых без доступа быть не может:

| Отказ | Что исчезает с экрана | Что остаётся |
|---|---|---|
| Local Network | Список найденных точек показа, адреса `192.168.*`, расхождение с проектором, список телевизоров | Звук из колонки площадки и запись показа после |
| Camera на `session` | Сканер кода | Ввод шестизначного кода цифрами |
| Camera на `clips` | Съёмка клипа | Просмотр клипов не затронут |
| Photo Library | Выбор файла из медиатеки | Съёмка видео камерой на площадке |
| Photo Add | Экспорт в «Фото» | Клип остаётся в «Моих записях» |
| Microphone | Индикатор «в эфире», уровень голоса, счётчик слушающих | Дорожка, записанная до показа |
| Location | Расстояния до площадок и порядок «ближе — дальше» | Расписание по выбранному городу |
| Push | Ничего не исчезает: уведомлений просто нет | Время начала и переносы в расписании вкладки |
| ATT | Персонализация рекламы | Реклама по разделу каталога |

**Сбой фичи ≠ отказ доступа.** Отдельные состояния с причиной человеческим языком: «Телевизор в подсобке отвечал 4 минуты назад, сейчас нет», «Проектор занят до 23:20», «Один телефон отстаёт на 1,8 с — далеко от точки доступа», «Запись не выкладывали: у оператора сел телефон», «Начался дождь, кино не досмотрели». Ни одно из них не связано с разрешениями и ни одно не ведёт в «Настройки».

**На старте промптов нет.** Первый системный алерт возможен не раньше экрана `ads`, и только по нажатию «Разрешить и продолжить»; путь «Продолжить без разрешения» ведёт на «Главную» без единого промпта.
