# Пайплайн v4: нативный, от идеи до сборки

Статус: **принятое направление**. Пайплайн переделывается полностью. Выход — не HTML-прототип,
а собираемое SwiftUI-приложение в симуляторе. Ядро переделывается под SwiftUI (не зеркалится с
`base.css`). Слой доступов сохраняется целиком и усиливается. На новом пайплайне первым собирается
«Петля».

Предпосылки — [WHY-REWORK.md](WHY-REWORK.md). Прежние наработки — [PIPELINE-NATIVE.md](PIPELINE-NATIVE.md),
[QUALITY-LOOP.md](QUALITY-LOOP.md).

---

## 1. Один источник правды, один целевой выход

`concept.json` остаётся единственным источником правды. Меняется бэкенд рендера: вместо
`kernel/*.css` + `screens/*.html` спека компилируется в Xcode-проект на SwiftUI.

```
concept.json ──► gen/gen-app.mjs ──► build/<slug>/  (Xcode-проект, SwiftUI)
                                     └─► xcodebuild ─► симулятор ─► скриншоты + журнал доступов
```

HTML-контур не переносится в новый пайплайн — он остаётся как есть на прежних ветках для истории,
но целевой выход теперь один: нативная сборка. «Полуручной режим» уходит: тела экранов больше не
пишутся руками рядом со спекой — они генерируются **из** спеки.

## 2. Граница генерации проходит по риску

| Детерминированно, кодом (ядро тренажёра) | Агентом, под измеряемые ворота |
|---|---|
| `Info.plist`: ключи и usage-строки **дословно** из `permissions[]` | Тело экрана: раскладка контента внутри паттерна |
| Слой доступов: запрос на своём `screen`/`gesture`, granted/denied/fallback | Тексты данных, `contentCases`, наполнение списков |
| Навигация: `TabView` + `NavigationStack` + `.sheet`/`.fullScreenCover` из `screens[].type` | Доводка отступов и типографики |
| Экраны входа: один каркас на все концепты | |
| Токены: акцент, шрифты, сетка из `brand` | |

Слева — то, что проверяет ревьюер App Store, и оно воспроизводимо посимвольно. Справа — то, где
ошибка видна на скриншоте и стоит одну итерацию.

## 3. SwiftUI-ядро (переделанное, не зеркало)

`platform/native/Kernel/` — рукописная библиотека SwiftUI, спроектированная под iOS, а не
перенесённая из CSS:

- **Tokens** — акцент/фон/типографика/сетка `16 / 44 / 72` как `EnvironmentValues` и модификаторы.
- **Компоненты** — `Row`, `SectionCard`, `Placeholder` (`.ph`), `DownloadRow` (`.dl`), `OTPField`,
  `StatusChip` — нативные вьюхи, а не span'ы с классами.
- **AuthFlow** — `phone → code → codefail → app`, один на все концепты, сверен с макетом.
- **Permissions** — `PermissionManager` поверх реальных iOS API (см. §4) + `PermissionGate`
  (модификатор: жест → системный запрос → granted/denied/fallback).
- **AppShell** — `TabView` c `NavigationStack` на вкладку, роутинг из типов экранов.

Ядро собирается один раз и копируется в каждый сгенерированный проект (детерминированно), чтобы
`.pbxproj` синхронизировал одну папку (`PBXFileSystemSynchronizedRootGroup`, Xcode 16+).

## 4. Слой доступов — сохранён и усилен

Все поля `permissions[]` остаются. Усиление — в том, что запрос идёт через **настоящие** iOS API,
а не через нашу JS-модель:

| key | iOS API |
|---|---|
| `camera` | `AVCaptureDevice.requestAccess(for: .video)` |
| `mic` | `AVAudioApplication.requestRecordPermission` |
| `speech` | `SFSpeechRecognizer.requestAuthorization` |
| `photo` | `PHPhotoLibrary.requestAuthorization(for: .readWrite)` |
| `location` | `CLLocationManager.requestWhenInUseAuthorization` |
| `push` | `UNUserNotificationCenter.requestAuthorization` |
| `tracking` | `ATTrackingManager.requestTrackingAuthorization` |
| `localnet` | Bonjour-браузер (`NWBrowser` / `NetServiceBrowser`) — триггерит системный промпт |
| `audio` | не запрос, а entitlement `UIBackgroundModes: audio` + `AVAudioSession` |

Инвариант «один доступ — одна точка запроса» теперь проверяется на реальном iOS (XCUITest со
сброшенными разрешениями симулятора), а не на эмуляции. Правила из `permissions[]` (`anchor`,
`conditional`, `requires`, `reviewNote`) переносятся один в один: `conditional` доступы не
запрашиваются, пока за ними нет живой фичи; `activate` (`audio`) не показывает алерт.

## 5. Порядок ворот переделан — дефект ловится рано

1. **Стратегия + позиционирование.** `mode: mimicry | differentiation`. Отстройка проще: у неё нет
   ворот паритета с референсом. Мимикрия обязана предъявить `referencePattern → screen →
   observable behavior` — до отрисовки.
2. **Карта «доступ → фича».** Ревью критиком (дизайнер/продакт), полстраницы, 10 минут. Пропуск
   невозможен: дальше ошибка стоит всей сборки.
3. **Вертикальный срез `entry → action → result`.** Генератор в статусе `draft` собирает **только
   три экрана среза**. 30 экранов до приёмки среза не рисуются физически — дорогая переделка
   становится дешёвой.
4. **Полная генерация** — только после принятого среза.
5. **Автоприёмка** — детерминированные ворота (см. §6).
6. **Критик-агент с квотой** вместо самоотчёта: на входе только скриншоты и спека, нет замысла
   автора. «Назови 5 экранов, которые выглядят сгенерированными, и по какому признаку.»

Оценку ставит тот, кто нашёл дефект, а не тот, кто допустил. `visualPasses`-самоотчёт удаляется.

## 6. Ворота автоприёмки

| Ворота | Как |
|---|---|
| Проект собирается | `xcodebuild` без ошибок и варнингов вне белого списка |
| `Info.plist` == `permissions[]` | линт: множество ключей плиста совпадает со спекой посимвольно |
| Достижимость экранов | из `screens[].parent/type` строится граф; недостижимый из `start` роняет сборку |
| Fallback на каждом триггере отказа | XCUITest со сброшенными разрешениями |
| Хит-таргет ≥ 44, контраст, обрезание | снапшот-тесты по PNG из симулятора |
| Паритет структуры | скриншот из симулятора и спека расходятся не больше порога |
| Журнал доступов | последовательность системных промптов в симуляторе == порядок из спеки |
| Плотность: КБ **на экран**, длина списков, ровные числа | измеряется, не самоотчёт |

Правило: **новое правило в CLAUDE.md заводится вместе с проверкой либо не заводится.**

## 7. Роли

Разработчик — автор всего цикла. Дизайнер/продакт — критик в двух точках, **не читая код**:
после карты «доступ → фича» (до отрисовки) и после зелёной сборки (ссылка/скриншоты/журнал
доступов, не Xcode). Ревью — ворота, а не пожелание.

## 8. Технические решения

- **SwiftUI по умолчанию**, UIKit точечно через `UIViewRepresentable`: камера (`AVCaptureSession`),
  `PHPicker`, `DataScannerViewController`, `CallKit`. Три-четыре обёртки в ядре, не выбор фреймворка.
- **iOS 17** минимум (`NavigationStack`, `Observable`).
- **Swift 5 language mode**, `SWIFT_STRICT_CONCURRENCY = minimal` — генерация не должна упираться в
  strict concurrency.
- **Проект генерируется, не коммитится** — в git только спека, ядро и генератор; `build/` в
  `.gitignore`. Нет merge-конфликтов в `.pbxproj`.
- **Медиа** — плейсхолдер `.ph` (нативный `Placeholder`). Генерация изображений — отдельный трек,
  не блокирует; правило «картинка никогда не обоснование доступа» сохраняется.

## 9. Что делаем сейчас

Собираем «Петлю» на новом пайплайне: генератор → Xcode-проект → зелёная сборка в симуляторе →
скриншоты. Сначала детерминированный каркас (Info.plist + навигация + слой доступов + вход +
экраны-заглушки из компонентов ядра), затем тела ключевых экранов среза (`lessons → lesson →
counter`) и раздела доступов.
