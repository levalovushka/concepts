# Как работает iOS-пайплайн

Пайплайн превращает короткое описание идеи в готовый нативный iOS-концепт.

## Как проходит работа

1. **Получает идею**

   На входе — короткое описание продукта, выбранный референс и стратегия:
   повторяем стиль референса или делаем самостоятельный нативный дизайн.

2. **Прорабатывает и выбирает продукт**

   Studio предлагает ровно три продуктовых механизма и сравнивает их, но не
   выбирает за человека. После явного выбора Product Core фиксирует аудиторию,
   ситуацию, проблему, сущности, действия, основной цикл и доказательство
   продукта. Экраны и разрешения на этом этапе запрещены.

3. **Добавляет возможности iOS**

   Камера, геолокация, уведомления и другие системные возможности привязываются
   только к уже существующим продуктовым действиям. Для каждой возможности
   задаются момент запроса, реальная операция платформы, видимый результат,
   запасной сценарий и тесты granted/denied.

4. **Собирает вертикальный срез**

   Сначала проектируются только три поверхности `entry → action → result`.
   Native Kernel детерминированно компилирует из контракта SwiftUI, reducers,
   маршруты, permission wiring, capture-инструментацию и XCUI. Генеративная
   модель не пишет инфраструктурный Swift-код.

5. **Проверяет и локально исправляет**

   Xcode собирает приложение, XCUI проверяет основной сценарий и обе ветки
   разрешений, а Simulator делает снимки реальных состояний. Независимый review
   возвращает типизированные дефекты. Допускается не больше двух локальных
   исправлений; Product Core при этом не регенерируется.

6. **Расширяет принятое ядро**

   Полное приложение появляется только после принятия вертикального среза.
   Full Contract обязан сохранить принятые экраны и закрыть пять корневых вкладок,
   владение действиями, journeys и capture matrix. Его также компилирует тот же
   Native Kernel, поэтому shell и разрешения не расходятся между итерациями.

## Что получается на выходе

- рабочий SwiftUI-код приложения;
- готовый Xcode-проект;
- описание продукта и его логики;
- набор экранов и состояний;
- автотесты основных сценариев;
- снимки приложения из симулятора;
- отчёт о сборке и визуальной проверке;
- понятный итог: приложение готово к передаче разработчику или требует исправлений.

Важно: исходники сами по себе не считаются готовым результатом. Концепт готов
только после успешной сборки, прохождения сценариев, свежих captures и визуальной
проверки.
