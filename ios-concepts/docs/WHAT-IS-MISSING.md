# Чего не хватает для сильного переноса всех HTML-концептов

1. Реальный structured-output model adapter для генерации содержательно разных Concept Candidates; fixture adapter доказывает воспроизводимость, но не заменяет модель.
2. Traceable evidence intake для insight, job, supply, cold start, core loop и retention. Сейчас gates проверяют provenance-ссылки, а не истинность продуктовой гипотезы.
3. Полные скриншотные наборы, reference family и mental model для VK Музыки, VK Видео и Одноклассников по спискам в `REFERENCE-PROFILES.md`.
4. Явные `concept.ux` контракты для следующего содержательного редизайна Looks/Dvor; текущая UX Specification честно помечена как legacy derivation.
5. Реальные примеры контента, включая длинные имена, тексты, пустые списки и ошибки. Детерминированные fixtures — тестовые данные, не пользовательское исследование.
6. Оригинальные фото/видео/обложки и подтверждённые правила лицензирования; цветные иконки-плейсхолдеры не принимаются. Legacy media отмечены как app-owned migration material, а не как новая лицензия.
7. Контракты backend/API для функций, которые нельзя честно реализовать локально.
8. Целевые устройства, минимальная iOS, дополнительные локали, light/dark и требования доступности за пределами текущего контракта.
9. Для нового VK-mimicry профиля — подтверждение product-chrome icon map. В нативном SwiftUI Looks и Dvor уже используют проверенный локальный Lucide 0.525.0 asset set только в системном `TabView`; permission/platform actions остаются SF Symbols. Случайные SVG и runtime-загрузка запрещены.

Без этих входов можно доказать полноту и внутреннюю согласованность контрактов,
но нельзя честно обещать market fit, точную мимикрию новых reference products,
реальную серверную логику и 10/10 для каждого состояния.
