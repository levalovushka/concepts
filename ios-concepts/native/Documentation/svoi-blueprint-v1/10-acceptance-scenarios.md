# Executable acceptance scenarios

XCUI must execute the action IDs in order and assert the observable result, not merely open screens.

| ID | Scenario | Start | Actions | Expected result | Recovery |
|---|---|---|---|---|---|
| accept-auth-feed | Локальный вход открывает наполненную ленту | login | request_email_code → verify_email_code → open_feed | После ввода показанного локального кода активна session-alex, а лента содержит deed-bench, deed-garden и deed-library. | Неверный код не создаёт сессию; можно запросить новый детерминированный код. |
| accept-publish | Пользователь публикует конкретное дело | create | create_deed → edit_deed_text → choose_deed_photo → choose_deed_place → publish_deed | Новое active-дело появляется первым среди дел близкого круга с импортированным фото и местом. | При пустом результате черновик сохраняется и показывается «Опишите конкретный результат.» |
| accept-social-response | Друг поддерживает дело, предлагает помощь и подписывается | feed | support_deed → offer_help → follow_result | У deed-bench увеличена поддержка, создан contribution kind=offer и user-marina записан в followers. | Повторная поддержка не дублируется; пустое предложение остаётся черновиком. |
| accept-comments | Комментарий открывается и создаётся отдельными действиями | feed | open_comments → respond_to_post | Открывается comments для deed-garden, а новый комментарий появляется в ветке и увеличивает commentCount. | Пустой текст не публикуется и экран комментариев остаётся открыт. |
| accept-progress-completion | Дело проходит от обновления до доказанного завершения | post_detail | add_update → add_contribution → choose_deed_photo → complete_deed → thank_helpers → take_baton | Исходное дело становится completed с доказательством и благодарностями; создаётся связанный черновик с parentDeedId. | Без доказательства завершение не применяется, обновления и вклады сохраняются. |
| accept-voice | Голосовое обновление записывается, расшифровывается и играет в фоне | post_detail | record_voice_update → transcribe_voice_update → play_voice_update | Update содержит audioPath, transcript и активный Now Playing с правильным названием дела. | При отказе в микрофоне или speech доступны текстовое обновление и ручная подпись. |
| accept-place-network | Участник подключается и подтверждает площадку | post_detail | join_deed_network → verify_site_network → add_contribution | Для deed-garden сохранены connected=true, verified=true и выполненный вклад участника. | При ошибке подключения показываются SSID и ручная инструкция; вклад можно подтвердить фото. |
| accept-message-call | Диалог поддерживает сообщение и локальный системный звонок | messages | open_conversation → send_message → start_helper_call | Сообщение delivered и завершённая запись CallKit-звонка появляются в conversation-marina. | Если звонок недоступен, диалог остаётся открыт и предлагает отправить сообщение. |
| accept-background | Подписка даёт наблюдаемое фоновое обновление | notifications | enable_result_alerts → apply_silent_snapshot → refresh_feed_on_fetch → schedule_digest_task | Версия snapshot повышена, fixture-обновление видно в ленте, а digest сообщает два изменения. | При запрете уведомлений данные обновляются при открытии и остаются в центре приложения. |
| accept-widget-session | Виджет публикует обновление от вошедшего пользователя | settings | share_session_with_widget → publish_quick_update_widget | update-widget-1 появляется в App Group, виджете и истории deed-bench от user-alex. | Без общей сессии виджет не показывает данные и открывает приложение для входа. |
| accept-private | Приватное дело защищено биометрией | private_deeds | unlock_private_deeds → open_deed | После успешной проверки видно deed-private; после ухода в фон список снова закрыт. | После отказа содержимое и заголовки приватных дел не раскрываются. |
| accept-link-calendar | Календарное событие возвращает в конкретное дело | post_detail | add_deadline_to_calendar → open_deed_link | Событие хранит Universal Link, который открывает deed-bench внутри приложения. | При запрете календаря срок остаётся в деле; неизвестный link показывает состояние отсутствующей записи. |
| accept-contacts-manual | Круг помощников пополняется без обязательного доступа к контактам | settings | import_helpers → search_world → open_search_result | При разрешении выбранный контакт добавлен в circle; при отказе тот же пользователь находится ручным поиском. | Отказ не блокирует создание дел, помощь и сообщения. |
| accept-tracking-denied | Отказ в tracking не влияет на основной цикл | settings | enable_promotion_measurement → open_feed → support_deed | Сохраняется contextualOnly, лента не меняет порядок, поддержка дела работает. | Настройку можно выключить; локальные продуктовые события продолжают собираться без межприложного идентификатора. |
| accept-credential | Credential Provider хранит идентификатор, но не обходит код | settings | manage_demo_credential → request_email_code → verify_email_code | Почта подставлена из provider record, новый локальный код проверен, новая сессия активна. | После удаления записи вход остаётся доступен ручным вводом почты. |
